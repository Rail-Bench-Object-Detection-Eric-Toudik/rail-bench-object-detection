\chapter{Methodology}
\label{ch:methodology}

\section{Approach}

Our methodology followed an iterative process consisting of dataset analysis, model selection, model adaptation, and experimental optimization. As a first step, we performed an explorative data analysis of the RAIL-BENCH dataset. The goal of this analysis was to gain a better understanding of the available training data, including class distributions, object sizes, annotation characteristics, and potential challenges arising from class imbalance. This preliminary investigation served as the basis for selecting suitable object detection architectures and designing subsequent experiments. Based on prior knowledge from deep learning and computer vision, the \acrshort{yolo} family was identified as a promising starting point due to its strong reputation in real-time object detection. To verify whether this assumption still holds for modern object detection benchmarks, we reviewed the evolution of the \acrshort{yolo} model family and analyzed recent developments in the literature (see Section~\ref{related_work_yolo11}). The review confirmed that \acrshort{yolo} remains one of the state-of-the-art approaches for object detection tasks. We additionally wanted to evaluate a transformer-based alternative. Consequently, we investigated recent state-of-the-art transformer architectures for efficient object detection. During this literature review, we identified EdgeCrafter as a particularly promising candidate.


\section{\acrshort{yolo}11-Based Approach}

For the RAIL-BENCH Object Detection Challenge, \acrshort{yolo}11 was selected as the primary object detection architecture among the \acrshort{yolo} family. This decision was motivated by the fact that \acrshort{yolo}11 represents the latest stable \acrshort{yolo} release and offers a mature software ecosystem with extensive documentation and community support. Although the more recent YOLO26 architecture introduces additional architectural advancements, the performance gains in object detection reported by Ultralytics are relatively small compared to \acrshort{yolo}11 (+3.4 \acrshort{map}) \cite{yolo26}. Consequently, \acrshort{yolo}11 was chosen as a robust and reproducible baseline that combines competitive performance with implementation stability, making it well suited for the objectives of the RAIL-BENCH Object Detection Challenge.

To assess the influence of model capacity on detection performance, pretrained weights provided by Ultralytics were used to initialize multiple \acrshort{yolo}11 variants. Specifically, the small (S), medium (M), and large (L) versions were fine-tuned on the RAIL-BENCH dataset. In addition, data augmentation techniques were integrated into the training pipeline to increase the diversity of the training data and improve model generalization. The augmentation pipeline was applied during training and formed the basis of all \acrshort{yolo}11 experiments conducted in this project. During the first training runs, we observed that certain classes achieved substantially lower detection performance than others. In particular, classes with relatively few training examples, such as bicycles, appeared to suffer from underrepresentation. To mitigate this issue, a simple oversampling strategy was investigated. Images containing underrepresented object classes were duplicated within the training dataset, thereby increasing the frequency with which these classes were observed during training. A further challenge emerged when analyzing predictions for small objects. We observed that small and distant objects, especially when belonging to underrepresented classes, were difficult for the detector to localize and classify accurately. To address this problem, we employed the \acrfull{sahi} framework. The key idea of \acrshort{sahi} is to decompose a large image into several smaller overlapping image slices, perform object detection independently on each slice, and subsequently merge the predictions into a single result \cite{sahi}. This approach effectively increases the relative size of small objects within each sliced image and can therefore improve small object detection performance. For our implementation, we utilized the official Python library provided by the authors \cite{sahi_library}.


\section{EdgeCrafter-Based Approach}

As discussed in Section~\ref{related_work_edgecrafter}, EdgeCrafter achieves a favorable balance between detection accuracy and computational efficiency through the combination of compact Vision Transformer backbones and task-specialized knowledge distillation. Given its strong accuracy-efficiency trade-off, compact model design, and explicit focus on deployment in resource-constrained edge environments, we considered EdgeCrafter to be particularly well suited for the RAIL-BENCH Object Detection Challenge. As railway perception systems are expected to operate under strict computational constraints while maintaining high detection performance, the characteristics of EdgeCrafter closely align with the constraints in existing railway infrastructure.

For our experiments, we selected the medium and large ECDet variants provided by the authors. Using the official training scripts released with EdgeCrafter, both model configurations were initialized with pretrained weights and subsequently fine-tuned on the RAIL-BENCH dataset. To ensure a fair comparison between EdgeCrafter and \acrshort{yolo}11, we applied the same optimization strategies whenever possible. Consequently, data augmentation was integrated into the EdgeCrafter training pipeline, \acrshort{sahi} was additionally evaluated as a small-object detection enhancement technique and also we increased the input resolution from 640 x 640 to 1024 x 1024 pixels to match with the input resolution in \acrshort{yolo}11.


\section{Hybrid ECDet Configuration}

Finally, we investigated whether the strengths of multiple EdgeCrafter configurations could be combined into a single detector. 
During our experiments, we observed that different ECDet configurations exhibited complementary behavior. 
One configuration achieved particularly strong performance on small objects, while another configuration produced more reliable detections for the remaining object classes. Based on these observations, we developed a hybrid detection approach that combines the strengths of both configurations. Rather than relying exclusively on a single model, predictions from the specialized ECDet variants were aggregated to leverage their complementary capabilities. The resulting hybrid configuration was subsequently evaluated alongside the individual \acrshort{yolo}11 and EdgeCrafter models.
